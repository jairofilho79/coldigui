A mudança nas listas

A busca por título/letra/número não muda. O que muda é o que acontece quando você monta uma reunião: hoje a app trata PDF e áudio como duas listas. A proposta é uma lista de louvores, cada um com o material que você escolheu.

Hoje, no código: pdfIds[] e audioIds[] separados + botão PDF | Áudio. Chordpro ou YouTube virariam a terceira fila. Isso é o que não escala.

1. O modelo (é só isso)

Hoje — duas caixas

Proposto — uma fila

Lista “Culto domingo”

1. 384 · Grande é o Senhor cifra ▾
também: partitura · áudio · YouTube
2. 412 · Porque Ele vive áudio ▾
também: cifra · gestos
3. 128 · A Deus seja a glória YouTube ▾

Uma ordem. “Próximo” vai 384 cifra → 412 áudio → 128 YouTube. Trocar o material é no item, não virar a lista inteira. Chordpro no futuro é mais um tipo no ▾ — não uma terceira caixa.

2. O botão que existe hoje

Na tela de playlists há um interruptor PDF | Áudio. Clique e veja as duas filas.

384 cifraPDF 1/2
412 partituraPDF 2/2
384 áudioÁudio 1/2
128 áudioÁudio 2/2

O 412 some na face áudio. O 128 some na face PDF. Não é a mesma reunião — são duas.

3. O vai-e-volta (hoje) vs ficar na lista

Hoje

Buscar louvor→ Sheet de material→ Abre o leitor→ Cria lista “não salva”→ Volta em Listas→ Carregar no carousel?→ Confirma substituir

Abrir um PDF e montar a reunião são caminhos diferentes que se esbarram.

Proposto

Buscar (título/letra/nº)→ + na lista ativa→ Toque abre o material→ Próximo = próximo da lista

“Nova lista” só quando você pede. “+” sem lista ativa cria a primeira. O leitor é a lista em tela cheia, não outro mundo.

5. Frase única

Hoje: “esta lista tem PDFs, e também tem áudios, em outra ordem.”
Proposto: “esta lista é a ordem da reunião; cada louvor diz qual material está ativo.”
